# 2단계 - 칸반 보드 관리(프로젝트)

## 기능 요구 사항

[디자인 시안](https://www.figma.com/design/3aBG3UfkTwmHM8BnPyahtT/8%EA%B8%B0-Android-%EB%A0%88%EB%B2%A81-%EB%AF%B8%EC%85%98-%EB%94%94%EC%9E%90%EC%9D%B8?node-id=23136-23&p=f&t=LUzbNSxrKJqeCpDp-0)
을 참고하여 칸반 보드 프로젝트를 구현한다.

기존 태스크 수정 다이얼로그에는 다음 기능이 추가된다.

* 담당자에 `"없음"` 상태 추가
* `"삭제"` 버튼 추가

---

## 프로그래밍 요구 사항

* 태스크 **생성 화면과 수정 화면의 공통 요소를 어떻게 재사용할지** 고려하여 설계한다.
* 불필요한 리컴포지션이 발생하지 않도록 상태를 관리한다.
* 적절한 테스트 방법을 활용해 기능 요구 사항을 검증한다.
* 모든 요구 사항이 테스트 가능한 것은 아니므로, 테스트 가능 여부를 구분한다.

---

## 구현할 기능 및 세부 명세

* [x] 상태가 TO_DO 일 때 다이얼로그에 담당자 `"없음"` 상태가 추가한다.
* [x] 기존 태스크 수정 다이얼로그에는 `"삭제"` 버튼이 추가되고 `추가`버튼 대신 `수정` 버튼이 생긴다.
* [x] 상태에 `Review`를 추가하고, 이에 따라 `Review` 컬럼을 생성한다.
* [x] Snackbar가 사용자 행동에 따라 서로 다른 메시지를 표시하도록 한다.
    * [x] Review or Done 상태에서 태스크를 삭제하려고 할 때
      "해당 상태에서는 태스크 삭제가 불가합니다." 라는 스낵바 노출
    * [x] 불가능한 상태 전이를 시도할 때
      "해당 상태로 옮길 수 없습니다." 라는 스낵바 노출
    * [x] 담당자를 지정하지 않고 In Progress로 전이할 때
      "담당자를 지정해야 상태를 옮길 수 있습니다." 라는 스낵바 노출
    * [x] 태스크가 수정 되었을 때
      "태스크가 수정되었습니다." 라는 스낵바 노출
    * [x] 태스크가 삭제 되었을 때
      "태스크가 삭제되었습니다." 라는 스낵바 노출
* [x] TaskCard 클릭 시 수정 및 삭제가 가능하도록 한다.
* [x] KanbanColumn의 개수가 증가할 경우, 좌우 스크롤이 가능하도록 한다.

### 비즈니스 로직

* [x] KanbanCard의 내용을 수정하거나 삭제할 수 있도록 한다.
* [x] `ToDo` 상태의 `KanbanCard`는 담당자 미지정을 허용한다.
* [x] 상태 전이 로직
    * [x] `ToDo` 상태의 `KanbanCard`는 `In Progress` 상태로만 전이할 수 있다.
    * [x] `In Progress` 상태의 `KanbanCard`는 `ToDo` 또는 `Review` 상태로만 전이할 수 있다.
    * [x] `Review` 상태의 `KanbanCard`는 `In Progress` 또는 `Done` 상태로만 전이할 수 있다.
    * [x] `Done` 상태의 `KanbanCard`는 `ToDo` 상태로만 전이할 수 있다.

## 이전 단계 구현 내용 요약

### 레벨1 - 칸반 보드 태스크(카드)

* 칸반 보드용 태스크 카드 UI를 구현했다.
* 카드 제목, 본문, 태그, 담당자 정보를 표시할 수 있도록 구성했다.
* 제목과 담당자 이름은 말줄임 처리했으며, 본문은 최대 2줄까지 표시되도록 구현했다.
* 태그는 최대 5개, 각 태그 이름은 최대 5글자까지만 노출되도록 제한했다.
* 본문이나 태그가 없는 경우 해당 영역을 렌더링하지 않도록 처리했다.

### 레벨2 - 칸반 보드 태스크(리팩터링)

* 비즈니스 로직과 UI 로직을 분리하는 방향으로 리팩터링했다.
* 제목(`title`)과 담당자 이름(`crewName`)에 대한 유효성 검증을 적용했다.
* 잘못된 입력값에 대해 예외가 발생하도록 단위 테스트를 작성했다.
* 예외 상황에서도 안정적으로 동작할 수 있도록 fallback 처리를 고려했다.

### 1단계 - 칸반 보드 생성(태스크 생성 모달)

* 새 태스크 생성 모달을 구현했다.
* 제목, 상태, 담당자를 필수 입력값으로 두고 설명과 태그는 선택 입력값으로 구성했다.
* 상태와 담당자는 기본값이 선택된 단일 선택 구조로 구현했다.
* 필수 입력값이 누락되거나 유효성 검증에 실패할 경우 생성 버튼이 비활성화되도록 처리했다.
* 에러 문구를 통해 입력 오류를 사용자에게 안내할 수 있도록 구현했다.

### 2단계 - 칸반 보드 생성(보드)

* 칸반 보드 화면을 구현하고, 태스크 생성 모달과 연결했다.
* 태스크를 상태별(To-Do, In Progress, Done)로 분류하여 컬럼에 배치했다.
* 전체 태스크 수와 Done 상태 태스크 수를 기반으로 완료율을 계산해 표시했다.
* 태스크 생성 시 새로운 `KanbanCard`를 리스트에 추가할 수 있도록 구현했다.

### 1단계 - 칸반 보드 관리(프로젝트)

* 여러 개의 칸반 보드를 관리할 수 있도록 사이드바 UI를 구현했다.
* 선택된 칸반 보드에 따라 우측 보드 화면이 변경되도록 상태를 관리했다.
* 드래그 앤 드롭을 통해 태스크 상태를 변경할 수 있도록 구현했다.
* 태스크 상태 변경 시 `"태스크가 이동되었습니다."` 스낵바를 통해 사용자에게 피드백을 제공했다.
* `KanbanProject`가 여러 `KanbanBoard`를 가지도록 구조를 확장했다.
* 카드 상태 변경 규칙을 비즈니스 로직으로 분리하여 처리했다.
